### The index-check ruling (orchestrator, under prompt 3 section 4)

- **The two sources.** Prompt 3 section 5.2 defaults to pending stubs "so CI is green from the first commit" (build-readiness decision 5), and phase 0's exit asks for `pnpm check` green "with the stubs counted". The PRD's D-33 "Until decided" line says: "No pending stub is created: under v1.5 the index check fails for each section 7 id with no case file (guardrails section 7; R-156), and the harness reports each such case as 'no automated check yet', never as passing."
- **The ruling.** The PRD line is the stricter one, because a stub that satisfies the index check with no test behind it may count as a loosening (guardrails section 10, "When unsure, treat the change as loosening"), and whether a stub counts as a case file is for the approver. So:
  - no pending stubs are created;
  - the index check fails for each section 7 id with no case file, and lists each as "no automated check yet";
  - a real case file whose test the pending wrapper keeps out of the green run (the field-state and evidence tests) counts as present, and is reported as "pending: no automated check yet", never as passing;
  - everything else in `pnpm check` must be green;
  - a stub generator, `tools/checks/index/generate-stubs.ts`, is written but not run.
- **Consequence.** Phase 0's exit item "`pnpm check` runs green with the stubs counted" does not hold until D-33 is decided. This is reported, not worked around.
- **Where recorded.** ADR 0003 (`docs/adr/0003-index-check-convention.md`), with how to reverse it.
- **Stricter choice logged.** Prompt 3 5.2 "Index-check convention" against the PRD's D-33 "Until decided" line; the PRD line is followed.

**P-0006-1. Clarification of rule 2, "Render test"** (from ADR 0006; for the approver, guardrails section 10). Revised in round 2 with its first line.

```diff
 - **Render test.** A rendered-screen test on every wizard step and dashboard fixture fails when a digit sequence appears outside an element bound to a value id. The allowlist covers dates and times, step numbers, character counters, and fixed interface copy on a reviewed list, such as "24 / 7", "3D / 2D" and "Max file size 500 MB".
+  - A number is bound only by a value id the screen was served a display object for, and only as that display object serves it: every number inside a value element is its formatted value, its lines or their declared parts, and a value element holds no other value element. A well-formed id the screen was not served binds nothing.
```
