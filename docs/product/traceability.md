### 8.2 What each dashboard page reads

For each dashboard page, and for the undesigned pages that show project values, what the page reads from **intake answers** (the owner's own candidates and decisions from steps 1 and 3 to 8, and later edits), from **document values** (candidates read from analysed documents, and what the engine calculates or estimates from them with approved datasets), and from **IFC values** (values read from a model). Pages drawn twice share one row and one set of stories (dashboards-spec 1.2 and 2.5).

- **One model, no copies.** Every figure comes from the one project model as a resolved field object, through the value or price component, with one badge, its source line and, on a demo project, the demo line (dashboards-spec 5; rule 2; 2.8). The same value id with the same filter renders identically on every page (G2-7), and a breakdown and its total come from one snapshot (G9-8). US-REVIEW-01 (the value component), US-REVIEW-02 (display precision and ranges) and US-REVIEW-03 (the demo line) apply to every row and are not repeated; nor are the shell, card and menu stories (US-ADMIN-06, US-ADMIN-07, US-ADMIN-08, US-ADMIN-12, US-ADMIN-13), which section 2 lists per screen.
- **IFC values: none on any page under v1.5.** A model is stored with "Not analysed: IFC model stored, not analysed" (US-IFC-01). What a page may show of it is its geometry converted for viewing, naming its document, with no label, count or area read from the model (US-IFC-08, US-MODEL-04), and only once the viewer is built (onboarding Q3). Every read of a model value named in the IFC column waits for at least ifc-input 6.2.1, 6.2.2, 6.2.3 and 6.2.10 and build-readiness decision 4, and its story is listed as gated.
- **Live content reads nothing in the proposal phase** (7.1-r27, 7.1.1-E2). It is listed in the E-OPS column.
- **Gated pages.** A page or element whose story waits for a proposal or an open question reads nothing while the gate is closed. Its row names what the drawn content would read, so the dependency is visible; that is data lineage, not a requirement.
