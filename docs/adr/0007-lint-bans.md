# 0007. Lint bans and package boundaries

- **Status:** Accepted: default, reversible
- **Date:** 2026-09-25 (amended 2026-09-25 at the end of phase 1)

## Context

Prompt 3 section 10 ("Phase 0") asks for lint bans on `?? 0`, `|| 0` and `Number()` on engineering values, on colour literals outside the tokens file and on `box-shadow`, and for dependency-cruiser rules enforcing the boundaries of section 6 ("Boundaries"). Section 5.4 adds that the registry's gate-opening test-utils entry may be imported only from `tests/proposed/`, and section 6 ("Brand assets") that focus rings use `outline`, because Tailwind's `ring-*` is built on box-shadow.

Sources: guardrails rule 1 ("Unknown propagates": "The lint check forbids `?? 0`, `|| 0` and `Number()` on engineering values"), rule 2 ("Enforced by": "The lint check forbids UI code from importing domain internals"), rule 8 ("Parsing") and rule 9 ("Rounding"); build-readiness 3 "Now" item 2; PRD R-156. The tools themselves (ESLint, dependency-cruiser) are the monorepo and tooling default recorded in ADR 0001, under **D-33**, which is open. The owner decided no D row as of 2026-09-25.

## Decision

1. **A local ESLint plugin**, `tools/eslint-rules/index.js`, with nine rules (seven, and since the phase 0 review round 2 also `no-total-outside-engine` and `no-computed-import`), spread last into `eslint.config.js` through `configs.recommended`:
   - `sovitech/no-zero-fallback`: `?? 0`, `|| 0`, `??= 0`, `||= 0`, a default of 0 in a parameter or destructuring pattern, and conditionals that fall back to 0 on the value they test, or whose other branch reads the value (or a property of it) that the test checks for being present; zero in any spelling (`0`, `0.0`, `-0`, `0n`, `'0'`, `` `0` ``, `Decimal(0)`). Since the phase 0 review (finding 22) it also resolves names bound to a zero: a `const`, a `let` or `var` written only by its initialiser, chains of such names, and a property of a const object literal whose value is a zero (through `as const` and `Object.freeze` too). With type information (`pnpm lint:eslint`), any name or property whose type is the literal `0`, `0n` or `'0'` counts, which catches a zero constant imported from another module; the `lint-bans` check lints without type information, so there only same-file constants resolve.
   - `sovitech/no-filtered-sum` (added after the phase 0 review, finding 22): a `filter` that drops missing values (`!== undefined`, `!= null`, `typeof`, `!!`, `instanceof`, `Boolean`, `isDefined`, `Number.isFinite` and the other presence checks in `lib/presence.js`, bare truthiness), or a `flatMap` that returns `[]` for a missing item, reached directly, through array steps or through a name that holds the filtered array, and then an arithmetic `reduce` or a `sum`, `total`, `mean`, `average`, `max` or `min` call. Totals go through the engine helper that applies a formula's `unknownPolicy` (phase 5); it gets an allowlist entry only after review. Since round 2 (adversarial finding 7; finding 4 of the second verification) it also bans a reducer whose inline callback does arithmetic and branches on a missing value, and a loop or per-item callback that folds values into a running total declared outside it while its body tests for a missing value, or over an array that already dropped its missing values. Not covered: an unrolled accumulation outside any loop or callback, recursion, a per-item function passed by name, a helper that hides the test; guardrail cases G1-2 and G1-5 test the behaviour itself.
   - `sovitech/no-total-outside-engine` (round 2, adversarial finding 7), on `apps/` and every package but `packages/engine` (`ENGINE` in `index.js`): additive reducers, running sums in loops and per-item callbacks, `Decimal.sum`, `Big.sum`, `BigNumber.sum` and `Math.sumPrecise`, whatever they test. Counting, text building, maxima and minima pass. Totals are made in the engine, by the helper that applies `unknownPolicy` (phase 5).
   - `sovitech/no-computed-import` (round 2, finding 0 of the second verification: `await import(dir + 'source')` in `apps/api` reached the gate issuer, and dependency-cruiser saw no edge), on all of `apps/` and `packages/`: `import()`, `require()` or `module.require()` with a path that is not written in the code, `require` used as a value, `createRequire`, `import.meta.glob` and `globEager`, `eval`, `Function` and `new Function`. A literal path passes; dependency-cruiser reads it.
   - `sovitech/no-number-coercion`: `Number()`, `new Number()`, `parseFloat`, `parseInt`, their `Number.` and `globalThis.` forms, `Number` passed as a function, unary `+`, and the bitwise idioms `| 0`, `~~`, `>>> 0`.
   - `sovitech/no-colour-literals` (JS and TS) and `sovitech/css-no-colour-literals` (CSS through `@eslint/css`): hex colours and colour functions anywhere, Tailwind palette and arbitrary colour classes, named colours in style values, and three.js colours. The theme's own `--color-*` names pass.
   - `sovitech/no-shadows` and `sovitech/css-no-shadows`: `box-shadow`, `text-shadow`, `drop-shadow()`, `feDropShadow`, and Tailwind's `shadow*`, `inset-shadow*`, `drop-shadow*`, `text-shadow*`, `ring*`, `inset-ring*` and `ring-offset*`. A theme reset to `initial` (which switches a Tailwind scale off) passes.
2. **Scope.** Every JS, TS and CSS file under `apps/` and `packages/` (`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`: `SCRIPT_EXTENSIONS` in `index.js`; `.mts` and `.cts` since round 2, adversarial finding 12, when they had no ESLint configuration at all), test files included; the `lint-bans` check also scans `.html`, `.htm` and `.xhtml` there, and fails any file under `apps/` or `packages/` with a script, component, style or markup extension no ban reads (`lint-bans/unread-extension`: `.vue`, `.svelte`, `.astro`, `.mdx`, `.scss`, `.less` and the rest of `EXTENSIONS_A_BAN_MUST_READ`). The roots are the "lint-bans" roots of the shared scan-roots list (`tools/checks/scan-roots/roots.json`; ADR 0009). `tools/`, `tests/`, `evals/`, `fixtures/`, `services/` and `company/` are outside the bans: test code and seeded inputs hold banned patterns on purpose, `services/` has its own Python bans (`services/extractor/tests/test_bans.py`, run by `pnpm test:py`), and `company/` is never an input.
3. **CSS in tolerant mode.** `@eslint/css` cannot parse Tailwind's `@theme` and `--color-*: initial` strictly, so it runs in tolerant mode, and the rules also read the raw text the parser leaves. ESLint therefore no longer reports general CSS syntax errors in app CSS; the Vite build still does.
4. **A four-entry allowlist** (`tools/eslint-rules/allowlist.js`, mirrored in `tools/eslint-rules/README.md`, and kept in step by `config.test.ts`):
   - `no-number-coercion`: `packages/registry/src/number-parser/**`, the one rule 8 number parser (phase 1 writes it there);
   - `no-number-coercion`: `packages/view-model/src/formatting/**`, the formatting module that owns rounding at display (rule 9; phase 3);
   - `no-number-coercion`: `apps/api/src/port.ts`, one function, `readPort`, which reads the listen port from `SOVITECH_API_PORT` (configuration, not a field of the value model). Until the phase 0 review (finding 22) the entry covered the whole API entry, `apps/api/src/index.ts`; `config.test.ts` now fails if `port.ts` holds anything but that function, and `port.test.ts` pins what it accepts (digits only, 1 to 65535);
   - `css-no-colour-literals`: `packages/ui/src/tokens.css`, the one tokens file.
   `no-zero-fallback`, `no-filtered-sum`, `no-total-outside-engine`, `no-computed-import`, `no-colour-literals` and the shadow rules allowlist nothing. `packages/engine` is outside `no-total-outside-engine` by the rule's scope, not an allowlist entry. The allowlist, the engine scope, `SCRIPT_EXTENSIONS` and `EXTENSIONS_A_BAN_MUST_READ` are all in the loosening check's exception-list snapshot (ADR 0005, decision 6; ADR 0010), so adding an allowlist entry or an exempt scope, or removing an extension, fails the loosening check until the approver approves it.
5. **dependency-cruiser** (`.dependency-cruiser.cjs`) with twelve forbidden rules: `no-company-imports`, `web-imports-only-browser-entries`, `db-only-from-api`, `view-model-server-only-from-api`, `ui-viewer-no-domain-engine-registry`, `gate-test-utils-only-from-proposed` (a reachability rule since round 2), `proposed-tests-only-from-proposed` and `no-tests-from-apps-or-packages` (both added in round 2), `package-internals-only-through-exports`, `packages-do-not-import-apps`, `browser-code-reaches-no-server-code` (a reachability rule) and `not-to-unresolvable`. Round 2 (adversarial finding 1) showed the test-utils rule forbade only a direct import: `apps/api/src/ingest.ts` -> `tests/proposed/open-gate.ts` -> test-utils, and a guardrail case through the same helper, passed. `pnpm lint:deps` cruises the "lint:deps" roots of `tools/checks/scan-roots/roots.json` through `tools/checks/scan-roots/lint-deps.ts` (round 2, adversarial finding 13), not roots written in the script. `package-internals-only-through-exports` was added after the phase 0 review (findings 0 and 11): outside its own package, a file under `packages/<pkg>/src/` is imported only through an entry in that package's `package.json` exports, read when the config loads, so a relative import of `packages/registry/src/gates/source.ts` can no longer open a gate. Each pattern matches the three forms an import resolves to (the path under `packages/`, a path through `node_modules/@sovitech/`, the bare name). Seeded inputs (`^tools/.*/seeded/`, `^tools/eslint-rules/fixtures/`) are excluded from the real run.
6. **The `lint-bans` check** (`tools/checks/lint-bans/`) runs the nine rules with inline configuration switched off, so an `eslint-disable` comment cannot hide a ban in `pnpm checks`; scans HTML pages; fails files no ban reads; runs dependency-cruiser on the `lint:deps` roots; and fails an empty scope (`lint-bans/scope`: an `apps/` or `packages/` folder with no file read, or a boundary run that read no module; phase 0 review, finding 17). Its self-test requires the good inputs to pass, then fails on 69 seeded bad inputs: 36 seeded bad folders (one broken ban each; the round 2 ones: a reducer and a loop that skip missing values, a loop over a filtered array, a reduce in a component and a loop in the view-model outside the engine, a computed gate-source import and `createRequire`, `?? 0` in an `.mts` and a `.cts` module, a `.vue` component and an `.scss` stylesheet no ban reads), 22 seeded bad imports in `tools/eslint-rules/fixtures/seeded/depcruise/`, and 11 gate-boundary imports in `tools/checks/loosening/seeded/boundary-imports/` (every expected boundary rule must fire; round 2 added two chains from `apps/api` to test-utils through `tests/proposed/`, a two-hop chain, a `tests/guardrails/_support/` chain, and `apps/` and `packages/` importing `tests/e2e/`). `tools/eslint-rules/depcruise.test.ts` copies the seeded boundary files into a temporary workspace shaped like the real one and runs the real CLI with the real config, and fails any forbidden rule that neither seed set proves; `tools/checks/loosening/boundary-seeds.test.ts` does the same for the gate-boundary seeds, rebuilds each earlier configuration from the current one (`expectations.json`, `before`), and shows that each earlier configuration let its probes through.
7. **Readings recorded for review** (`tools/eslint-rules/README.md`, "Readings recorded for review"):
   - broader than the letter: the bans cover all of `apps/` and `packages/`, not only `packages/*/src`; the zero ban also covers defaults, conditionals and names bound to a zero; `no-filtered-sum` covers averages, maxima and minima as well as sums, and any test for a missing value in a loop that keeps a running total; `no-total-outside-engine` bans every running sum outside the engine, layout offsets included; `no-computed-import` also bans `createRequire`, `import.meta.glob`, `eval` and `Function`; the `lint-bans` check fails a file no ban reads; the number ban covers the bitwise idioms; the shadow ban `text-shadow`, `drop-shadow()` and `feDropShadow`; six boundary rules go beyond the section 6 list (`browser-code-reaches-no-server-code`, `not-to-unresolvable`, `packages-do-not-import-apps`, `package-internals-only-through-exports`, `proposed-tests-only-from-proposed`, `no-tests-from-apps-or-packages`);
   - narrower than the letter: "Only `apps/api` imports `db` and `view-model/server`" is read as production code, so guardrail case files in `tests/guardrails/` and `tests/proposed/` may import both (an indexed case such as G4-20 must drive the database layer from its case file); `tests/e2e/` may not;
   - "internals" is read as any file: `ui` and `viewer` import nothing from domain, engine or registry, entry points included;
   - named colours are reported only where a style value is expected; hex colours, colour functions and Tailwind colour classes are reported in any string.

## Consequences

- Code in `apps/` and `packages/` cannot default a value to 0 (literally or through a zero constant), total a filtered array that dropped its unknowns or keep a running total that skips them, make a total outside the engine, load a module by a computed path, coerce a number by hand, write a colour outside the tokens file, draw a shadow, reach into another package's internals or import test code, and an `eslint-disable` comment does not change that in `pnpm checks`. Non-engineering running sums outside the engine (layout offsets) must be rewritten or allowlisted after review.
- Non-engineering code pays a small cost: an explicit value instead of a default of 0, `Number.isInteger` instead of a coercion. The first effect was on `packages/registry/src/validation/sensitivity.ts`, whose `answersTried = 0` default was replaced by an explicit argument.
- The number parser and the formatting module must be written at the allowlisted paths, or the allowlist and its README table change together (`config.test.ts` enforces that).
- Guardrail case files may import `db` and the view-model server side directly (reading 2). This is listed for the owner's review in the build log.
- `.svg` files are not linted for colours: the brand logos are copied verbatim with their SHA-256 (prompt 3 section 6). An SVG written for the app belongs inline in a component, where the colour rules read it.
- No section 7 case id covers the bans or the boundaries; they are R-156 harness checks, proven by 435 RuleTester cases (101 for `no-zero-fallback`, 9 of them typed; 96 for `no-filtered-sum`; 44 for `no-total-outside-engine`; 28 for `no-computed-import`), the boundary fixture tests and the `lint-bans` self-test.
- **Not yet banned** (adversarial finding 7, remainder; buildable now, planned for the next phase 0 or phase 1 round in this folder): `Decimal` or `new Decimal` built from a non-literal string outside the rule 8 parser (type-aware), `JSON.parse` on text, rounding (`toFixed`, `toPrecision`, `Math.round`, `floor`, `ceil`, `trunc`, `Intl.NumberFormat`, `toLocaleString`) outside the formatting module, and zero-initialised tallies (`new Array(n).fill(0)`, `Object.fromEntries(keys.map((k) => [k, 0]))`). Until then the allowlist entries for the parser and the formatting module keep only the number-coercion ban at those paths; no lint rule yet keeps rounding in the formatting module.
- **Phase 0 review (2026-09-25).** Findings 0 and 11 (a gate opened by a relative import), 17 (a pass on an empty scope) and 22 (zero constants, filtered sums, the whole API entry exempt from the number ban) were fixed here, each with seeded inputs the old configuration let through. They are harness near misses with no section 7 case; the change-log row is owed when phase 1 next edits `docs/guardrails.md`.
- **Phase 0 review, round 2 (2026-09-25).** Adversarial findings 1 (the test-utils rule held only a direct import), 7 (reducers and loops that skip unknowns; totals outside the engine), 12 (`.mts` and `.cts` unlinted) and 13 (fixed scan roots), and finding 0 of the second verification (a computed import), were fixed here, each with seeded inputs the old configuration let through. Also harness near misses with no section 7 case.

## How to reverse

- A rule: remove its entry from `configs.recommended` in `tools/eslint-rules/index.js`, and its row from the README. A boundary: remove its entry from `forbidden` in `.dependency-cruiser.cjs`, with its seeded files and `expectations.json` lines.
- The default-of-0 part of `no-zero-fallback`: set `'sovitech/no-zero-fallback': ['error', { defaults: false }]` in `index.js`.
- Reading 2 made literal: remove `CASE_FOLDERS` from the two `pathNot` lists in `.dependency-cruiser.cjs`; the cases must then reach the database through `apps/api`.
- The inline-disable guard: set `allowInlineConfig: true` in `tools/checks/lint-bans/lint-bans.ts`, or drop the `lint-bans` check (and its entry in `EXPECTED_CHECKS`).

Each of these lets more code through, so each is listed in the build log for the owner's review before it is made.

## Phase 1 amendment (2026-09-25)

The rest of adversarial finding 7 (round 2) is built: thirteen ESLint rules and thirteen dependency-cruiser boundaries.

- **Extended rules.** `no-zero-fallback` also bans a zero floor (`Math.max(x, 0)`) and `|| []` / `||= []`. `no-number-coercion` also bans arithmetic that changes no number (`x - 0`, `x * 1`, `1 * x`, `x / 1`, `x + 0`, `x ** 1`), `Number.call`, `.apply` and `.bind`, `const { Number: N } = globalThis`, `Number[name]`, `globalThis[name]` with a computed name and, with type information, any callee typed as the Number constructor.
- **Four new rules.** `no-decimal-from-text` (a `Decimal`, `Big` or `BigNumber` built from text, typed and untyped forms; exempt scope `NUMBER_PARSER`, the rule 8 parser), `no-json-parse` (exempt the reviewed readers of `JSON_PARSE_REVIEWED`: `packages/registry/src/validation/snapshot.ts` and `packages/registry/src/test-utils/test-utils.test.ts`), `no-rounding-outside-formatting` (`Math.round`, `floor`, `ceil`, `trunc`, `fround`, `toFixed`, `toPrecision`, `toLocaleString`, `Intl.NumberFormat` and decimal rounding; exempt scope `FORMATTING_MODULE`) and `no-zero-tally` (`.fill(0)`, `Array.from(..., () => 0)`, `fromEntries` or `Map` of `[k, 0]` pairs, `{ [k]: 0 }`, `tally[k] = 0`, `.set(k, 0)`; no exemption). The three exempt scopes are exported from `index.js`, like `ENGINE`, and are three new exception lists recorded in unapproved baseline v0 on 2026-09-25 (`lint-bans.decimal-from-text-exempt`, `lint-bans.rounding-exempt`, `lint-bans.json-parse-reviewed`), so a scope or reader added now waits for the approver.
- **A thirteenth boundary** (integration, phase 1): `test-formulas-and-fixtures-only-from-tests` forbids any chain of imports from `apps/*/src/` or `packages/*/src/` to `packages/engine/test-formulas/` or `fixtures/` (prompt 3 sections 5.4 and 10: TEST formulas and datasets load only inside the test runner; until then this held by convention, backed by `loadDataset` refusing any TEST id). Two seeded imports prove it (`packages/engine/src/imports-test-formulas.ts`, `apps/api/src/imports-fixture-dataset.ts` in `tools/eslint-rules/fixtures/seeded/depcruise/`).
- **Seeds.** The lint-bans self-test runs 88 seeded bad inputs (69 before phase 1): 14 new seeded bad folders and the two new boundary seeds, with RuleTester files for each new rule (typed cases for the alias and text forms) and config scope tests; and, since the phase 1 review, the three seeded bad imports of the boundary `db-testing-only-from-tests` (from `apps/api`, from `packages/engine` and from a store file that is not a test).
- **Consequences.** Rule 8's parsing (decimals and `JSON.parse` on text) and rule 9's rounding now have a lint check; "Not yet banned" above is closed. The first run of `no-zero-tally` flagged phase 0 harness code in `packages/domain/src/not-implemented.ts`, which now counts from a list of thrown features (a near miss in the guardrails 1.6 change log). Not banned or not covered, each documented in `tools/eslint-rules/README.md`: `?? []` (registry code reads optional lists that way; totals over such lists are banned outside the engine), `BigInt(text)` (the domain's decimal comparison uses it on a JavaScript number's own text), `Response.json()`, typed arrays (which zero-fill by themselves) and `Math.min(x, 0)`. The bans are strict: `Math.floor` for layout or indices, and `toLocaleString` for dates, are banned outside the formatting module, and any future `JSON.parse` in `apps/` or `packages/` needs a reviewed reader, which now waits for the approver.
