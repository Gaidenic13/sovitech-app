# 0046. The viewer spike: That Open Engine on web-ifc, in the sandbox, measured on the fixtures and the perf model

- **Status:** Proposed (the owner decides D-03 from the measurements below; no viewer is wired into the live app)
- **Date:** 2026-10-02 (planner: context, decision, dependencies); amended and measured by the spike builder on 2026-10-02 (decisions 1 to 4 as built, decisions 6 to 9, "Consequences", "How to reverse", "Measurements"); amended in phase 4 part B, 2026-10-02 (decision 7 and Finding 11: the screenshots erased with the model, A-11)

## Context

- **Prompt 3 5.2, "Model viewer"** (ifc-input 2.2): "That Open Engine (`@thatopen/components`, `@thatopen/fragments`, `three`) fed with Fragments converted once on the server. IfcOpenShell's GLB and SVG output as the fallback and as the source of printed plans. Settle it with a spike in phase 4 and record the measurements." Prompt 3 section 8: conversion runs once on the server, keyed by project id plus content hash, in a container with no network, a read-only input mount, and memory and time limits; "Measure web-ifc's memory in the phase 4 spike: it is wasm32, so 4 GB is its ceiling"; the browser never parses the owner's IFC. Section 11's budgets (ADR 0041): on a `perf` IFC4 file of about 100 MB, the viewer conversion within 15 minutes under 4 GB; first view within 5 seconds; orbiting at 30 fps or better on integrated graphics with the tab under 1.5 GB; storeys on demand; the viewer code-split.
- **The owner's answer of 2026-10-02** (build log, "Owner answers during the run"), to the question whether to build a minimal viewer before `ifc-values` opens: "Trial now, decide later (Recommended)". The spike runs on the synthetic fixture models and the `perf` model, in the sandbox, and records time and memory here; no viewer is wired into the live app; every page that would draw a model area renders without one (PRD R-078 "Until decided"; R-080); the owner decides D-03 from these measurements. D-01 and D-04 stay open.
- **The owner's answer of 2026-09-26:** IFC is read with web-ifc (MPL-2.0), not IfcOpenShell (its wheels bundle GPL CGAL packages; ADR 0018), so the IfcConvert fallback of 5.2 is not available; plans would come from the same converted geometry (a section of it), drawn as inline SVG with no text (prompt 3 section 8; ifc-input 5.4 IFC-12).
- **No public sample model is downloaded** (prompt 3 section 12: "Ask before downloading any public sample model"; not asked). ifc-input 2.2's "one large public sample" is replaced by the synthetic `perf` profile (`fixtures/ifc/perf/demo-hotel-perf.ifc`, about 101 MB: 186 storeys, 22,264 spaces, 157,166 elements, 179,430 extruded solids; git-ignored).
- **The working rules for phase 4:** new packages only from npm, pinned exactly, MIT, BSD, Apache, ISC, MPL or OFL only (AGPL or GPL: stop and report), each in an ADR; no binary from GitHub.

## Decision

1. **A separate workspace package, `packages/viewer-spike` (`@sovitech/viewer-spike`)**, imported by nothing but itself and the proposed suite (the dependency-cruiser rule `viewer-spike-imported-by-nothing`, proven by five seeded imports in `tools/eslint-rules/fixtures/seeded/depcruise/`: from `apps/web`, `apps/api`, `packages/viewer` and `tests/e2e` refused, from `tests/proposed/` allowed, so ifc-input 5.4's IFC-12 can read the plan input of decision 8): the converter (`src/convert/`, Node: That Open's `IfcImporter` on web-ifc writes Fragments in the view profile of decision 6), the plan cutter (`src/plan/`, decision 8), and the bench page (`src/bench/`: `@thatopen/components` with `FragmentsManager` (That Open's `FragmentsModels`), three and camera-controls, loading one converted model). **Amended as built:** the runner is not `src/run/` but `tools/viewer-spike/` (`run.ts`, `sandbox.ts`, `server.ts`, `processes.ts`, `stats.ts`, with a README): it reads process listings and the converter's summary as text, which the app's lint bans refuse in `packages/` (`no-number-coercion`, `no-json-parse`), and it is a measuring harness like `tools/run-render.ts`. It reaches the package by path only (esbuild bundles the bench page; Docker runs the converter), never by import. It serves the bench, the Fragments worker (`@thatopen/fragments/dist/Worker/worker.min.mjs`) and the brand tokens from a static server bound to 127.0.0.1 with a fixed path table; no web-ifc WebAssembly is served, because the browser opens Fragments only and never an IFC file. `packages/viewer` stays the live viewer's home and is not changed.
2. **The conversion runs in the sandbox**, an image `services/viewer-spike/Dockerfile` (`sovitech-viewer-spike:dev`) built like the IFC reader's (`services/ifc-reader/Dockerfile`: Node 22.17.1 slim pinned by the same digest; packages from the committed lockfile with `--frozen-lockfile`; one bundled file, `cli.mjs`, with @thatopen/fragments and three inside it; web-ifc's Node build, its WebAssembly and its licence beside it; an unprivileged account, uid 10001; a 2 GB V8 heap). The root `.dockerignore` lets in `packages/viewer-spike/package.json`, `src/convert/` and `src/plan/` and nothing else of the package. The runner (`tools/viewer-spike/sandbox.ts`) applies the reader's flags as `apps/api/src/jobs/sandbox.ts` writes them: `--network none`, `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--user 10001:10001`, `--pids-limit 256`, `--memory` equal to `--memory-swap` at 4g, `--cpus 2`, a 64 MB noexec `/tmp`, the model bind-mounted read-only, and one writable place, `/output`: a tmpfs volume of 512 MiB that no host folder backs, kept mounted by a holder so the files outlive the job, copied out through the Docker daemon and checked to be regular files; a wall clock of 15 minutes (the budget); containers and volume removed whatever happened. That Open's defaults that reach the network are replaced by local paths: the importer's web-ifc folder is an absolute local path or the converter refuses it, and the bench passes the worker's URL on its own origin. The converter prints a code only and writes `summary.json` with sizes, times and memory only (rule 13).
3. **What is measured, per model** (the four fixture models and the `perf` model): conversion wall time seen from the host, the importer's own time, the converter's peak resident memory (`process.resourceUsage().maxRSS`) and the container's peak memory (cgroup v2 `memory.peak`, which also counts the tmpfs output and the page cache); Fragments output size; in Chromium (viewport 1440×900, device scale 1): time from navigation start to the first frame drawn after the model's tiles are ready (`trianglesAtFirstFrame` shows something was drawn), frames per second over a 10-second orbit held from the keyboard (ArrowLeft held down; the time of every frame the renderer drew), the page's JavaScript heap (`performance.memory`; `performance.measureUserAgentSpecificMemory()` under cross-origin isolation where Chromium offers it), the peak resident memory of Chromium's renderer and GPU processes (sampled every 250 ms with `ps` over the browser's process tree), and the time to show each storey alone (Page Up, up to eight steps from the lowest storey, then Home). **As built, both graphics backends were measured:** Playwright's headless shell renders with SwiftShader (software WebGL), and Playwright's full Chromium in its new headless mode, with `--use-angle=metal --enable-gpu --ignore-gpu-blocklist`, renders on the machine's GPU, an Apple M1 Pro's integrated GPU, which is the budget's condition ("integrated graphics"). Each measurement names its backend.
4. **What the spike never does:** no model text is drawn in the scene, in textures or in a plan (rule 2; ifc-input 6.2.15); no value is read from a model for any screen; no log line carries model text (rule 13: codes, GlobalIds and STEP ids only); nothing is uploaded anywhere; no public sample is fetched. **As built, the bench checks this about itself on every run** (`src/bench/audit.ts`): the scene holds no sprite, points, textured material, text geometry or page element placed by the scene; the view holds one canvas and no other visible element (That Open's logo, which its renderer adds by default, is removed); the page's only text is the key help, read by assistive technology, with no digit and nothing from the model; there is no selection, hover or label; storeys are stepped through without labels; every camera move has a key (arrows held to orbit, plus and minus to zoom, W, A, S and D to move, Page Up and Page Down for the storeys, Home for the whole model), and the runner drives the view with the keyboard only (Tab reaches it).

6. **The view profile** (`src/convert/importer.ts`; built by the spike builder). While `ifc-values` is closed a model is shown as a document and nothing is read from it (prompt 3 section 8), so the converted file keeps only what a view needs: the shapes, the GlobalIds (the join to the register once the gate opens) and the spatial tree (to step through storeys). The importer is given an exclusion set that "has" every attribute name but `GlobalId` (`EveryAttributeExcept`), so it drops every attribute it meets, whatever the schema names it; no abstract class (property sets, quantity sets, materials, types, units); only the aggregation and containment relations; no elevation recomputed from placements. The importer always copies the STEP header's FILE_NAME and FILE_DESCRIPTION into the model's metadata, so the metadata is emptied afterwards with Fragments' own editor (`withoutHeaderMetadata`). The importer writes a random model id unless given one, so a fixed id (`CONVERTED_MODEL_ID`) makes a conversion reproducible. Proven in `src/convert/convert.test.ts`: of the strings each fixture model's STEP text quotes (ARH, MEP rev A, IFC2X3), only GlobalIds remain in the converted file; the library's defaults keep more than twenty of them (names, property values, the header); two conversions give the same bytes.
7. **Derived files are keyed and erased as the live store keys and erases them** (rule 13; ifc-input 6.2.16's stricter choice, built in phase 2). The runner writes each Fragments file at the store's derived path, `<root>/<projectId>/<sha256:…>/derived/viewer.frag` (`apps/api/src/storage/file-store.ts`, `derivedPath`), with a fresh project id per run, and erases it with the store's own `removeHash` after its model is measured; the results record the files keyed to the hash before and after (one, then none). The bench's screenshots of the rendered model are derived files too: since phase 4 part B (A-11; Finding 11) they are written under the same `derived/` folder (`bench-first-view.png`, `bench-after-orbit.png`, `bench-view.png`; `tools/viewer-spike/outputs.ts`) and erased with it, also when the measuring fails, and the erasure step checks the results folder for images as well (four files keyed to the hash before, none after, and no image in the results, or the run stops; `tools/viewer-spike/outputs.test.ts`).
8. **Plans from the converted geometry** (`src/plan/section.ts`, `storeyPlans`). IfcConvert is not available (owner decision 2026-09-26), so each storey's plan is cut from the same Fragments file with That Open's section helper (`getSection`), at 1.2 m above the lowest point of the storey's shapes (storeys ordered by their shapes' heights, never by a name or an elevation attribute), and drawn as one inline SVG path in the page's colour (`currentColor`) with no text, title, description, image or embedded content. A storey with no shape to cut has no plan, and the page that would show it reads "Not available yet" with its reason (rule 7; ifc-input 6.3.2). Proven in `src/plan/section.test.ts` on the ARH and MEP rev A fixtures (no text element, no character data between tags, no colour literal, none of the model's storey, space or equipment names). This is IFC-12's plan input; IFC-12 itself (an inline SVG plan with an area printed into it fails the render test) is the e2e builder's `tests/proposed/IFC-12*.test.ts`, which may import `storeyPlans` from `packages/viewer-spike/src/index.ts` (the dependency rule of decision 1 allows `tests/proposed/`).
9. **The converter can cut the plans in the sandbox too** (`--plans yes`): it records how long all storeys took and each plan's size, and writes no plan file.

## Consequences

- The owner gets measured numbers for D-03 without a viewer in the live app; the live pages keep their no-model behaviour (R-078, R-080). Nothing under `apps/` or in another package imports the spike (`pnpm lint:deps`: no violation).
- The spike's packages are in the lockfile and the licence check's scope, but in no app's bundle (the web's initial JavaScript is unchanged; ADR 0041's web budget).
- If the owner decides to build the viewer, `packages/viewer` takes the components, the conversion moves into the worker's sandboxed jobs keyed by project id plus content hash (erased with its document) with the view profile of decision 6, and the `view-provenance` and `ifc-values` gates keep their closed behaviour until approved. The findings below list what such a build must change in That Open's defaults.
- The spike adds no indexed case: its proofs are the package's own tests (`packages/viewer-spike/src/**/*.test.ts`, in the blocking unit run, titled "ADR 0046" and "ifc-input 5.4 IFC-12 (plan input)"), the runner's (`tools/viewer-spike/stats.test.ts`) and the dependency rule's seeds.
- The root `.dockerignore` names the spike's converter and plan sources (decision 2); the sandbox image is built locally (`docker build -f services/viewer-spike/Dockerfile -t sovitech-viewer-spike:dev .`) and is not part of `pnpm check`.

## How to reverse

Delete `packages/viewer-spike`, `services/viewer-spike` and `tools/viewer-spike`; drop the `viewer-spike-imported-by-nothing` rule from `.dependency-cruiser.cjs` with its five seeded files, their `expectations.json` lines and its row in `tools/eslint-rules/README.md`; remove the three `packages/viewer-spike` lines from `.dockerignore`; remove the image (`docker image rm sovitech-viewer-spike:dev`); and run `pnpm install`. Nothing else depends on them.

### Findings

1. **Network defaults.** That Open fetches from unpkg by default in three places: `FragmentsModels.getWorker()` and `FragmentsManager.getWorker()` (the worker), `IfcLoader.autoSetWasm()` (web-ifc's WebAssembly), and the importer's relative web-ifc path. The spike replaces all three with local paths; the sandbox (`--network none`) and the bench's request route found no attempt.
2. **A third-party mark in the view.** `SimpleRenderer` adds That Open Company's logo (an inline SVG labelled "That Open Company", in its own green) to the view by default. The bench removes it; a live viewer must too (the brand, app-alignment; no colour outside the tokens).
3. **The importer opens the model twice** (a geometry pass and a property pass, each with a new web-ifc instance). Peak memory stayed under 0.8 GB for the `perf` model.
4. **The header is copied into every converted file.** Emptying it with Fragments' editor costs 10 to 15 seconds on the `perf` model, a fifth to a quarter of the conversion.
5. **The view profile holds no model text but GlobalIds** (decision 6); the library's defaults hold names, property values and the header.
6. **Plans from Fragments' section helper** leave spaces out (the helper skips IfcSpace) and are cut from shapes only: the ARH fixture's storeys hold spaces and slabs, and only one of them also holds the doors and the lift, so only one of its six storeys has lines; the `perf` model has lines on 185 of 186. The helper's buffer holds at most 100,000 segments a section (the largest `perf` plan used 960).
7. **Software rendering is not usable for a large model:** 1 frame per second, and building the storey index in the page (185 box requests to the worker) took four minutes. A viewer needs a check for a missing GPU, and the storey index should be written at conversion, not computed in the page.
8. **The `perf` model is repetitive** (the test building's floor, repeated): Fragments keeps one shape per repeated element, so 101 MB of IFC became 8.9 MiB. A real model repeats less, so its converted file, load time and memory will be larger. Measuring one real large model needs the owner's yes to download a public sample (prompt 3 section 12; not asked).
9. **Chromium's page memory measurement** (`measureUserAgentSpecificMemory`) is offered by the full Chromium build only, not by the headless shell; the processes' resident sizes are measured in both.
10. **A lines-only plan does not pass the render test as it stands** (found by the integrator, `tests/proposed/IFC-12.test.ts`, 2026-10-02). The render test reads an inline SVG larger than an icon as pixels it cannot read (G2-1's `unreadable-pixels`), so the ARH fixture's storey plan, with no text, fails it, as a plan with an area printed into it does (on that number too). Showing a plan would need a reviewed `render.unreadable` entry, a loosening: proposal P-4-PLAN-UNREADABLE in `docs/build-log.md`, phase 4.
11. **The screenshots stayed after the erasure** (found by part B's adversarial review, A-11, 2026-10-02; rule 13, "Erasure": every file derived from a document goes with it; ifc-input 6.2.16's stricter choice). The runner wrote each model's three bench screenshots (`<model>-first-view.png`, `<model>-after-orbit.png`, `<model>.png`) into `<work>/results/`, outside the model's hash folder, while the erasure step counted only the files keyed to the hash: `results.json` recorded `{ filesBefore: 1, filesAfter: 0 }` for the `perf` and ARH models while six pictures of the rendered models remained, and the runner's docstring said nothing it writes holds model text. The fixtures are synthetic, so nothing of an owner's leaked.
