# 0017. The closed unit registry and the rule 8 number parser

- **Status:** Accepted: default, reversible
- **Date:** 2026-09-25

## Context

- **Guardrails 2.7:** units are registry entries with an ASCII code, a display symbol and a dimension; "The validator rejects any candidate whose unit dimension differs from its field's dimension. That dimension check is how 'kW and kWh are never interchangeable' is enforced." **Rule 8** gives the table of units by dimension, the qualifiers, the floor structure and "Parsing" (locale per table or per value, the Romanian format, "Ambiguous readings keep both", approximate wording kept, plausibility checks never auto-corrected).
- **Prompt 3 section 7:** "Units come from a closed registry with a dimension check. A value whose unit cannot be mapped gives no quantity candidate." Section 6 places "the rule 8 number parser" in `packages/registry`, and the lint allowlist (ADR 0007) exempts `packages/registry/src/number-parser/**` from the number-coercion and decimal-from-text bans. Section 5.2, "Floors notation" (onboarding Q7): floors by level type from the regim de înălțime, parts with no source Unknown.
- **Functions:** F-REGISTRY-02 (units), F-REGISTRY-03 (the parser), F-VALUE-09 (plausibility). **Cases:** G8-4 and G8-10 (phase 1, real); G8-1, G8-2, G8-3, G8-6 and G8-9 are evals that use the parser from phase 2.
- **D rows:** D-93 (plausible ranges and area-basis factors, with SOVITECH engineering); none decided as of 2026-09-25.

## Decision

1. **A closed list of 48 units** (`packages/registry/src/units/units.ts`) in rule 8's table order. Each has an ASCII code, a symbol, a dimension, the written forms it accepts (`mp`, `mc`, `mCA`, `kWh/an`, `lei` and the like) and, where rule 8 fixes one, a lossless factor to its base unit, with energy counted in joules. Letter case is kept, so `MW` is not `mW`. An ambiguous written form, such as Romanian `ml` (millilitre or metre run), maps to nothing.
2. **Dimensions are split where no lossless factor joins the units** (stricter than one row per dimension of rule 8's table): `kvs`, `kVA`, `kVAr`, `K` (differences), `%RH`, `m head`, `Nm3` and `DN` are each their own dimension, so none of them passes the check into a kW, °C, Pa, flow, m³ or length field. Legacy units (kcal/h, Gcal/h, TR, BTU/h, Gcal) and currencies carry no factor: rule 8 converts them by calculation with a stated definition or rate.
3. **The dimension check** (`packages/registry/src/units/check.ts`): `checkQuantityUnit(field, quantity)` refuses `unit_unknown`, `field_unit_unknown`, `field_takes_no_quantity` and `dimension_mismatch`, and no quantity candidate is formed (G8-4). `compareAcrossUnits` and `inBaseUnit` compare on BigInt decimals, with no rounding.
4. **The parser** (`packages/registry/src/number-parser/`). `parseNumber(text, { locale? })` reads the Romanian and English formats per value and keeps both readings of an ambiguous text ("1.500" reads as 1.5 or 1500), marked ambiguous, choosing neither. A locale hint settles only a text that reads two ways; a text that reads one way keeps that reading and is marked `hintContradicted`. It keeps rule 8's approximate words and the text exactly as written, and refuses a number that a JavaScript double cannot hold exactly. `parseQuantityText` maps the unit through the registry and refuses `unit_unknown`.
5. **The floor notation** (`parseFloorNotation`). The regim de înălțime is read into counts by level type from the letters of rule 8's own example "3S+P+Mz+12E+Er" only: S, P, Mz, E, Er (amended in the phase 1 review, below; the first version also read D, Et and M). An unknown part is `unrecognised`; a level type written twice gets no count; nothing reads as zero; roof plant never comes from the notation.
6. **Plausibility** (`packages/registry/src/units/plausibility.ts`; F-VALUE-09). `checkPlausibility(field, quantity, { verification })` returns `no_range`, `within`, `outside` or `not_comparable`, with the Please check badge and `usableInTotals`. A value the check cannot compare with the field's range (a legacy unit with no lossless factor) is held as if outside it. The check clears only with `engineer_verified`, or `user_confirmed` on an owner or either field; `owner_acknowledged` never clears it. The production registry holds no plausible range (ADR 0010; D-93), so there the check reports `no_range`; G8-10 runs with a TEST range.
7. **TEST homes** (prompt 3 sections 5.4 and 10): TEST formulas live in `packages/engine/test-formulas/` (typechecked through `packages/engine/tsconfig.json`), TEST datasets are generated by `fixtures/datasets/generate.ts` and listed in `fixtures/manifest.json`; both are loaded only by the sensitivity suite (`tools/checks/registry/sensitivity-suite.ts`) and the case files. Since phase 1 the dependency-cruiser rule `test-formulas-and-fixtures-only-from-tests` forbids any chain of imports from app or package source to either (ADR 0007), and `loadDataset` refuses any TEST id.

## Consequences

- A value in a unit the registry does not know, or in the wrong dimension, gives no quantity candidate; the field stays Unknown (rule 1). A value and a unit the split dimensions keep apart (kW and kVA, say) never compare.
- An ambiguous number never becomes one value silently; the right person settles it (rule 8, G8-3).
- Rule 8 asks each area to record whether it includes below-ground areas and parking (yes, no or unknown). Encoding those flags into the qualifier would let a partly unknown qualifier read as a known one and escape rule 4's comparison, so only the basis (`gross_total`, or unknown) is a qualifier today. The flags need a qualifier design the domain compares when part of it is unknown (phase 2, with the domain).
- Whether the notation letters count as glossary items (rule 8 routes abbreviation expansion through the glossary) is for the approver; the parser is first used in phase 2 (G8-9). Until then only the letters rule 8's example shows are read (phase 1 review amendment).

## How to reverse

Merging dimensions, adding written forms or accepting an ambiguous form lets more values through, so each is a loosening under guardrails section 10 and needs the approver's own words. Removing a form, or splitting a dimension further, is a tightening, recorded here and listed for the approver. The parser's per-value locale and "keep both" behaviour are rule 8's own text and are not a choice.

## Phase 1 review amendment (2026-09-25)

- **Decision 1, the count** (verifier finding 8): the registry holds 48 units, not 49 as first written here and in the build log. `units.test.ts` now pins the count ("holds 48 units, as ADR 0017 records"), so the documents cannot drift from it unnoticed. The build log's two mentions (status table, F-REGISTRY-02 row) are the integrator's to correct.
- **Decision 5, the letters** (verifier finding 9): rule 8 expands abbreviations "only from the glossary in reference data", and the Romanian glossary is not approved (gate `dataset-glossary`, closed; D-92 for the review, D-37 for whether it is an approved dataset; D-18 for the floors notation). The first version expanded D (demisol), Et (etaj tehnic) and M (mansardă) in code, beyond rule 8's own example "3S+P+Mz+12E+Er". The parser now reads only S, P, Mz, E and Er (`FLOOR_NOTATION_LETTERS`); a part with any other letter is `unrecognised`, its level type stays Unknown and the text is kept as written (`original`). Proof: `number-parser.test.ts`, "expands no letter beyond rule 8's example while the glossary is not approved". Whether D, Et and M join (as glossary entries, once an approved version names them) waits for the approver; the item is listed for the build log's "Waiting for approval, datasets or decisions".
- **Decision 7, the TEST datasets** (verifier finding 10, adversarial finding 20): their values sat inside real-world ranges (intensities of 100 to 150 per m², costs of 10 to 21 per m², savings of 2 to 8 %) and read as engineering and price data once out of their file. `fixtures/datasets/generate.ts` now writes every number from 9001 to 9099 (`SYNTHETIC_LOW`, `SYNTHETIC_HIGH`), keeping each table's order and a distinct value per option, so the sensitivity test still sees every answer (30 of 30); the four tables whose numbers moved are version `TEST-2`, and `fixtures/manifest.json` holds the new hashes. Proof: `tools/checks/registry/test-datasets.test.ts` (TEST in each id, version and description; no number outside the band; the files are what the generator writes).
- **Consequence.** A regim de înălțime with a semi-basement, a technical floor or an attic gives no count for those levels until the approver decides: those parts read Unknown (rule 8: "Parts with no source are Unknown"), never zero. A Speed cost, not a Truth one.
- **How to reverse.** Adding D, Et or M back to `LETTERS` in `packages/registry/src/number-parser/floor-notation.ts` expands an abbreviation outside the glossary: a loosening that needs the approver's own words, or an approved glossary version that names the letters.

## Phase 1 review, round 3 amendment (2026-09-25): the registry and the letters in the loosening snapshot

- **The failure** (adversarial finding 4). "How to reverse" above calls merging dimensions, adding written forms and accepting an ambiguous form loosenings, and decision 5's amendment calls a letter beyond rule 8's example one; yet the unit registry and `FLOOR_NOTATION_LETTERS` were in no snapshot (the letters were held by a unit test alone, and editing a test's expected result is itself a section 10 loosening no check saw). In a probe, kVA merged into power in the registry bundle passed validation and the loosening check.
- **The change.** "Unapproved baseline v0" now records the closed registry (`units`: per code its symbol, dimension, written forms and factor) and the letters (`floorNotationLetters`, from the new export `FLOOR_NOTATION_LEVEL_TYPES`, each letter with the level type it names), read from `units.ts` and `floor-notation.ts` themselves ([ADR 0010](0010-registry-values-unapproved-baseline.md), round 3 amendment). Against it, a unit added, a written form added, a dimension, symbol or factor changed, a factor where none was, a letter added or a letter naming another level type is a loosening that fails the check and that the writer refuses; a unit, a form, a factor or a letter removed is a tightening the writer records with its date. Registry validation, in the production scope, refuses a bundle unit that is not the closed registry's entry (`unit-not-in-closed-registry`), so the bundle the fields' dimension check reads cannot drift from the registry derive reads.
- **Recorded on 2026-09-25**: 48 units in 30 dimensions, 62 written forms, 36 factors; the letters S, P, Mz, E and Er. None is approved (D-05).
- **Proof.** Loosening seeds `unit-written-form-added`, `unit-dimensions-merged`, `unit-added`, `floor-letter-added`; registry seed `unit-not-in-closed-registry`; `snapshot.test.ts` ("compareSnapshots, formulas, datasets, units and floor-notation letters"); `loosening.test.ts` (the written form, the merged dimension and the letter D against the repository's baseline).
- **How to reverse.** Taking the registry or the letters out of the snapshot, or dropping the bundle rule, lets a widening pass unseen: a loosening that needs the approver's own words.
