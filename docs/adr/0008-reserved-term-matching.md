# 0008. Reserved-term list, matching and allowances

- **Status:** Accepted: default, reversible
- **Date:** 2026-09-25

## Context

Guardrails 2.8 ("Reserved terms") keeps one shared list of English and Romanian terms, used by the copy check and by the AI output validator. Matching is whole-word and ignores case and diacritics. The terms are allowed only in action labels, in badges, status lines and generated sentences that the app builds from stored state, in verbatim document text shown as a cited excerpt, and in registry qualifier labels; they are flagged everywhere else. Removing a term loosens the rules (section 10).

Prompt 3 section 7 ("Reserved terms") puts the list in `packages/registry` and has the check cover UI strings, templates, seeds, AI output, exports and rendered pages; phase 0 asks for the check with a self-test on seeded bad strings in both languages and diacritic forms. Sources: build-readiness 3 "Now" item 2 ("one reserved-term list and its checker, matching whole words and ignoring case and diacritics"); PRD R-156 and F-REGISTRY-05; case ids G10-1 and G11-6 (not yet built). The tools are the D-33 default recorded in ADR 0001; D-33 is open.

## Decision

1. **One list, one module.** `packages/registry/src/reserved-terms.ts` holds `RESERVED_TERMS_EN` (21 terms) and `RESERVED_TERMS_RO` (14 terms), copied character for character and in the order of 2.8, including î, ă and the comma-below ț. The package entry `@sovitech/registry/reserved-terms` re-exports it (`packages/registry/src/reserved-terms/index.ts`). A unit test and the check itself compare both lists with `docs/guardrails.md` 2.8 on every run ("drift"), so a term removed in code fails as a loosening and a term added in 2.8 fails until the code follows.
2. **Normalisation before matching.** NFKD with combining marks stripped, lower case, soft hyphens and zero-width characters removed, and any whitespace (line breaks and non-breaking spaces included) read as one space. So "oferta ferma" and "OFERTA FERMA" match "ofertă fermă", and the cedilla forms ş and ţ match the comma-below forms ș and ț.
3. **Whole words.** A match needs no letter, digit or underscore on either side. Multi-word terms match across whitespace and line breaks, and, since the phase 0 review (finding 12), across one hyphen or dash with no space around it, so "firm-price", "in-line-with" and "oferta-ferma" match. A spaced dash, a double hyphen and an underscore do not join words (an underscore is a word character in snake_case keys, so "firm_price" is not matched). Where terms overlap, only the longest is reported. Each match keeps its offsets in the original text. Inflected forms ("offers", "garantează") are not matched, exactly as 2.8 says; adding verb forms is proposal 7.2.29 and is not applied. The hyphen joiner matches more text, so it is a tightening, listed for the approver in the build log.
4. **Allowances are typed entries, never free text.** Five kinds: `action_label`, `badge`, `status_line`, `generated_sentence` (a template with `{slot}` placeholders that must list the stored state it reads) and `qualifier_label`. `createAllowanceSet` rejects an unknown kind, unknown keys, empty fields, an entry whose fixed text holds no reserved term, and a duplicate id. An allowance exempts only a whole copy unit that matches it exactly (whitespace normalised). There is no exemption by path and no free-text exemption. `REGISTERED_ALLOWANCE_ENTRIES` is empty in phase 0; phase 1 fills it from the badge, status-line, action, sentence-template and qualifier registries.
5. **Verbatim document text** is a scan context, not an allowance: `scanCopy(text, { context: { kind: 'verbatim_document_text', documentId, contentHash } })`. Both fields are required, so only text tied to a stored document revision is exempt.
6. **The check** (`tools/checks/reserved-terms/`) parses `.ts`, `.tsx`, `.js` and `.jsx` with the TypeScript AST under `apps/**` and `packages/**/src/**`, and reads HTML text and copy attributes, CSS `content` strings and every string value of a registered string catalogue (`STRING_CATALOGUES`, empty until phase 3). Copy units are string literals, template text (each `${}` read as `{}`), JSX text joined per element, and copy-type JSX attributes. Not copy: comments, import and export paths, type-level string literals, property keys (computed keys included), tagged templates (SQL, CSS), and technical attributes (`className`, `data-*` and the like). **Lower-case single-token strings** (since the phase 0 review, finding 12, which showed `{ done: 'final', checked: 'verified' }` and `issued ? 'binding' : 'draft'` passing, although CSS `text-transform` shows them as "FINAL" and "VERIFIED"): such a string is copy unless it sits in a type, as a property key, on one side of an `===` or `!==` comparison, as a `switch` case, or as a direct element of a list registered in `tools/checks/reserved-terms/machine-keys.ts` (`MACHINE_KEY_LISTS`: a `const` array literal or an enum of identifiers, each entry with its path, constant and reason). The check fails an entry whose file or constant does not exist, so no entry outlives its list. `MACHINE_KEY_LISTS` is empty in phase 0; each entry lets its strings through and is a reserved-term exception (prompt 3 section 13), listed for the approver before it is relied on. `==` and `!=` comparisons are not exempt. The earlier rule (a lower-case key is not copy unless it is the value of a copy property) is withdrawn. It skips test files, `docs/**`, and the `DEFAULT_IGNORES` of `tools/checks/lib.ts` (`company/**`, seeded folders, installed and generated files). In the list module, only the initialisers of `RESERVED_TERMS_EN` and `RESERVED_TERMS_RO` are skipped (`LIST_MODULE` in `tools/checks/reserved-terms/scan.ts`).
   **Superseded in part by the phase 0 review, round 2** (adversarial finding 3, whose probe passed with "6 files, 4 copy units" while holding capitalised terms as object keys, tagged templates, attributes on custom components, `data-*` values, a JSON copy file, SVG text, an input value, and a template and a migration outside `src`). Since then:
   - **Property keys.** A string key that is not a machine key ("Formal quotation", "Firm price") is copy wherever it stands, and every key of an object whose keys are handed out (`Object.keys`, `entries`, `values`, `getOwnPropertyNames`, `Reflect.ownKeys`, `for ... in`) is copy, identifier and lower-case keys included. The object is found by name across all scanned scripts: directly, through imports under their exported names, through property chains, and through spreads, to a fixed point.
   - **Tagged templates** are read (`` t`...` ``, `String.raw` by its raw text, SQL tags).
   - **Attributes.** Technical attribute names are skipped only on intrinsic elements; on a custom component every attribute is read except `key` and `ref`. `data-*` values are read. HTML also reads `value`, `aria-valuetext`, `aria-placeholder`, `aria-roledescription` and `data-*`, and text before and after the tags.
   - **Scope.** All of `apps/**` and `packages/**`, not only `src`, plus optional top-level `seed/`, `seeds/`, `migrations/` and `templates/`, and every glob the shared scan-roots list names for this check (`scanGlobs('reserved-terms')`, `tools/checks/scan-roots/roots.json`; ADR 0009), read from the list at load.
   - **File types.** Scripts (`.mts` and `.cts` included), HTML and SVG, CSS, JSON and JSONC, YAML (values, and keys that are not machine keys), SQL string literals, text templates (Handlebars, Mustache, EJS, Nunjucks, Liquid, Jinja) and Markdown or plain text. Any other file in scope fails, unless it is a registered string catalogue or matches the reviewed `NON_COPY_FILES` list (`tools/checks/reserved-terms/non-copy.ts`), whose one entry, `**/README.md`, keeps what the earlier scan skipped silently. An entry with no reason, or one that matches no file, fails. `NON_COPY_FILES` is a reserved-term exception in the sense of prompt 3 section 13: it is in the loosening check's exception-list snapshot, so an added entry fails until the approver approves it.
   - **Rendered pages.** The render harness now runs the same matcher over every copy unit of each checked page (ADR 0006, decision 8), so what the screen shows is read whatever its source form.
7. **An empty scope fails** (phase 0 review, finding 17): the check fails when an include root matches no file, when a registered string catalogue matches no file, or when it reads 0 copy units.
8. **Seeded bad inputs:** 31 trees and one good tree (19 until round 2). The first 11: English JSX, Romanian with diacritics, plain upper-case Romanian, the cedilla ţ, a multi-word term split across lines, an HTML title and meta tag, a copy property, a catalogue, stray copy in the list module, drift from 2.8, and a free-text allowance. Added after the phase 0 review, each one the earlier check let through: a label map (`'final'`, `'verified'`, `'quote'`, `'deviz'`), a ternary (`'binding'`), a variable (`'confirmat'`), a hyphenated term (`'firm-price'` as a key-like label and in a sentence), a machine-key list (a stale or missing registration fails; "Final offer" inside a registered list is still flagged, `'final'` there is not), an empty scope, no copy units, and a catalogue with no files. Added in round 2, each a form the round 2 probe showed passing: an object-key label, a tagged template, a component attribute, a `data-*` attribute, an HTML input value, SVG text (the SVG is written at run time, because an `.svg` in the repository is a document type outside its home), a JSON copy file, a file the check cannot read, a template outside `src`, an SQL migration, a seed file, and a malformed non-copy list. The good tree shows every allowed position.

## Consequences

- Every string literal in `apps/**` and `packages/**` is scanned, developer-facing error messages and JSON and YAML values included (4,562 copy units in 87 files on 2026-09-25, 2 READMEs not read). A later message that uses a reserved term fails `pnpm check`; the first run flagged one in `packages/registry/src/validation/validate.ts`, which was reworded. Exempting such messages would need a new allowance kind, which is a loosening.
- Rendered pages are read since round 2: the render harness scans each checked page's copy units (ADR 0006, decision 8), and an evidence excerpt passes only when the served display objects declare it. Exports are not read yet (phase 5), and `reserved_term_blocked` is logged once guardrail events exist (guardrails section 8; phase 1 database, phase 3 screens).
- Phase 1 heads-up: the check reads JSON and YAML under `packages/**`, so a label written as a value (a loosening-snapshot label such as "badge:engineer-verified", say) fails it; keep such text in keys, or propose a reviewed non-copy entry.
- `services/extractor/src` is not in this check's scope: the extractor emits codes only (prompt 3 section 8). Phase 2 adds it if the extractor ever writes finding text.
- No section 7 case covers the list yet: G10-1 and G11-6 are the reserved-term cases R-156 names, and they wait for phase 5. The list, matcher and check are proven by unit tests and the self-test only.
- **Phase 0 review (2026-09-25).** Findings 12 (lower-case labels and hyphenated terms passed) and 17 (a pass on an empty scope) were fixed here. Both are tightenings: more text is flagged. They are harness near misses with no section 7 case; the change-log row is owed when phase 1 next edits `docs/guardrails.md`.
- **Phase 0 review, round 2 (2026-09-25).** Adversarial finding 3 (copy in common source forms, and no rendered-page scan) was fixed here and in ADR 0006. Every change flags more; the one new exception entry, `NON_COPY_FILES` `**/README.md`, keeps the earlier behaviour for those files and is listed for the owner. A harness near miss with no section 7 case.
- The check's own tools now import the list through `@sovitech/registry/reserved-terms`, the package entry, as the dependency-cruiser rule `package-internals-only-through-exports` requires (ADR 0007).

## How to reverse

- The matcher's normalisation or boundary rule: change `foldForMatching` and `findReservedTerms` in `packages/registry/src/reserved-terms.ts` with their tests. A change that matches less text is a loosening.
- An allowance kind: remove it from `ALLOWANCE_FIELDS`; adding one is a loosening and needs the approver.
- The scan scope: change `include` in `tools/checks/reserved-terms/scan.ts`, or the reserved-term scans in `tools/checks/scan-roots/roots.json`; narrowing either is a loosening (the scan-roots entries are in the loosening check's exception-list snapshot).
- A non-copy entry: remove it from `NON_COPY_FILES`; adding one is a loosening.
- The position rule for lower-case strings: change `isCopy` in `tools/checks/reserved-terms/extract.ts` with its seeds; an entry in `MACHINE_KEY_LISTS` is the reviewed way to let a list of identifiers through, and each is a loosening for the approver.
- The hyphen joiner: remove it from `findReservedTerms` with the `bad-hyphenated-term` seed; that matches less text, so it is a loosening.
- If the list moves, update `LIST_MODULE.path`, the only place the list constants are skipped.
