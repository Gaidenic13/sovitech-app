# 0009. Repository checks: version sync, fixture manifest, licences, config exclusion, mockup and company figures, and scan roots

- **Status:** Accepted: default, reversible
- **Date:** 2026-09-25

## Context

Prompt 3 section 10 ("Phase 0") asks for these checks next to the index, reserved-term and registry checks:
- the version-sync check: `CLAUDE.md`'s "Checked against" line and the header of `prompts/sovitech-ai-system.md` against the guardrails version, and any `SKILL.md` the build adds (guardrails section 10, "Versioning": "CI fails when it differs"; build-readiness 2: "Every `SKILL.md` carries 'Checked against: docs/guardrails.md vX'");
- the fixture-manifest check: every fixture has a generator and its hash matches, and no document-type file sits outside `fixtures/` (guardrails rule 13, "The repo"; build-readiness 2, "CI fails on any fixture file without a generator"; prompt 3 section 14, item 7);
- the licence check: fails on AGPL or GPL dependencies and reports LGPL and MPL ones, reading the licence files inside the IfcOpenShell wheel too (prompt 3 section 8, "Licences"; ifc-input 2.3; section 13, item 7);
- the config-exclusion check: fails when any config reaches into `company/` (prompt 3 section 6; build-readiness decision 12);
- the mockup-figure grep of prompt 3 section 14, item 3, against `tools/checks/mockup-figures.txt`, built from the distinctive figures in the specs' transcriptions (added after the phase 0 review, finding 6, which found the list missing);
- since the phase 0 review round 2: the company-figure check against `tools/checks/company-figures.txt` (adversarial finding 8: only imports from `company/` were blocked, so a figure or a SAUTER product name typed by hand from `company/` entered the app unread, and the `dataset-sauter-catalogue` gate's closed behaviour had no automated check; prompt 3 section 7: "Never copy a figure ... from `company/`"; guardrails rule 1 "Identifiers and prices", G1-12, G1-3, G2-5), and the scan-roots check (adversarial finding 13: every scan named its own fixed roots, so a new folder for the demo seed escaped them all).

The tools are the D-33 default recorded in ADR 0001; D-33 is open, and the owner decided no D row as of 2026-09-25. Each check lives in `tools/checks/<name>/`, returns a `CheckResult` and has a self-test on seeded bad inputs (`tools/checks/README.md`).

## Decision

**Version sync** (`tools/checks/version-sync/`).
- Reads the single `**Version:** MAJOR.MINOR` line within the first 20 lines of `docs/guardrails.md`.
- That version must match every "Checked against" line in `CLAUDE.md` (at least one must exist), the line in the opening HTML comment of `prompts/sovitech-ai-system.md` and any other such line in that file, and every such line in `.claude/skills/*/SKILL.md` and `.claude/agents/*.md`. A mention of "Checked against" whose version cannot be read fails.
- A project skill without the line fails. A third-party skill recorded in `skills-lock.json` (today `frontend-design`, installed from anthropics/skills) is checked only when it carries a line, and is otherwise reported as a note. Build-readiness 2 asks every `SKILL.md` to carry the line; phase 0 may not edit `.claude/skills/frontend-design`, so this is reported in the build log, not fixed.
- 10 seeded bad trees, with neutral names so no tool mistakes them for real instructions or skills.

**Fixture manifest** (`tools/checks/fixture-manifest/`, schema version 1, validated with zod).
- `fixtures/manifest.json` holds `version`, `sources` and `files`. A source is a path with a role: `generator`, `generator-input` (which names the generator that uses it, `usedBy`) or `documentation`. A file entry holds `path`, `sha256` and `generator`, and optionally `generatorVersion`, `cases`, `groundTruth`, `profile`, `schema` and `toolVersions`.
- Every file under `fixtures/` must be listed, except `fixtures/ifc/perf/**` (git-ignored `perf` output, never listed), `manifest.json`, `.gitkeep`, `.DS_Store` and `__pycache__`. Each hash must match; each generator must exist, must not be under `company/`, and must be listed as a source when it sits under `fixtures/`. No file is listed twice, and no listed file may be missing.
- There is no "hand-written fixture" role: a hand-written test dataset under `fixtures/datasets/` is either produced by a listed generator or is a `generator-input` with `usedBy`.
- **Regeneration** (phase 0 review round 2, adversarial finding 9: only the recorded hash was compared, so a listed file with any generator passed, an owner document included). Every non-empty `files` list is re-run: each generator runs from the root as `<runner> <generator> --out <temp folder>` (TypeScript and JavaScript through the repository's tsx, Python through the extractor venv or `python3`; `GENERATOR_RUNNERS`), with a minimal environment and a 300 s timeout, and each listed file must come out with the manifest's SHA-256. A generator that fails, has no known runner, does not produce a listed file, produces different bytes, or changes anything under `fixtures/` while it runs, fails the check. No generator exists yet; the CI regeneration job in the no-network container and a double run for determinism are phase 2.
- Document-type files may sit only under `fixtures/`, `design/reference/` and `packages/ui/src/brand/`, and since round 2 each home only for its own types (`DOCUMENT_HOME_TYPES`): `design/reference/` png, jpg and webp; `packages/ui/src/brand/` svg, woff2 and woff; `fixtures/` any type, under the manifest. Both other homes are walked and checked by extension and by content signature (two font signatures, WOFF and WOFF2, count only in the brand home). Since the phase 0 review (finding 15, which found phone photos, scans, CSV exports, office, model, archive and mail formats missed), a document type is any of 51 extensions in six families, in any letter case: PDF; images (`jpg`, `jpeg`, `png`, `heic`, `heif`, `tif`, `tiff`, `webp`, `gif`, `bmp`); office (`doc`, `docx`, `xls`, `xlsx`, `xlsm`, `xlsb`, `csv`, `odt`, `ods`, `odp`, `odg`, `rtf`, `ppt`, `pptx`, `vsd`, `vsdx`); models (`ifc`, `ifczip`, `ifcxml`, `rvt`, `rfa`, `dwg`, `dxf`, `dwf`, `dwfx`, `dgn`, `nwd`, `nwc`, `pln`, `skp`); archives (`zip`, `7z`, `rar`, `tar`, `gz`, `tgz`, `bz2`, `xz`); mail (`msg`, `eml`). The check also fails closed on content: 18 file signatures (PDF, ZIP and OOXML, OLE, IFC STEP, DWG, DXF, PNG, JPEG, GIF, TIFF, WebP, HEIC and HEIF, BMP, 7z, RAR, gzip, tar, RTF) catch a renamed document with any extension. Round 2 (finding 15 of the second verification: `.avif`, `.mp4`, `.mov` and `.svg` exports passed) added `avif`, a video family (`mp4`, `mov`, `m4v`, `avi`, `webm`, `mkv`, `3gp`) and a vector family (`svg`), 60 extensions in eight families, and the signatures AVIF, ISO media `ftyp`, QuickTime, Matroska and WebM, AVI and SVG, 24 in all.
- **Embedded documents** (round 2). A text file outside `fixtures/` fails when it holds a base64 `data:` URI, or a bare base64 run, that decodes to a document signature (a PDF in a test helper, a JPEG in an HTML page). Test pages keep URL-encoded SVG `data:` URIs or build raster images at run time.
- The check reads both the files on disk (git-ignored ones included; installed and generated folders skipped) and `git ls-files`. `company/` is never read: it is skipped on disk and left out of `git ls-files` with a pathspec (before the review the check listed its tracked paths; now 49 tracked paths are read instead of 334). It does not skip `tools/**/seeded/**`, so seeded document-type inputs are generated in `os.tmpdir()` at run time.
- Phase 0 created `fixtures/manifest.json` as `{ "version": 1, "sources": [], "files": [] }`.
- 28 seeded bad inputs: 10 static seeded bad trees, plus 18 bad cases built in a temporary folder at run time (the 2 original ones; after the review, one per new family and one of 18 renamed files: `bad-document-images`, `-office`, `-models`, `-archives`, `-mail`, `-content`; after round 2, `bad-fixture-without-real-generator`, `bad-generator-output-differs`, `bad-generator-fails`, `bad-generator-no-runner`, `bad-generator-writes-repository`, `bad-document-in-design-reference`, `bad-document-in-brand`, `bad-document-media`, `bad-document-media-content`, `bad-embedded-documents`), and 2 good trees. The good trees include a CSV and an IFC fixture listed in `fixtures/` and reproduced by a real TEST generator, a PDF under a `company/` stand-in, text files that start with "BM" and "PK", and base64-like text, none of which may be flagged.
- **Not built: pinning `company/`.** Round 2 proposed failing any file added under `company/` by pinning git's tracked paths and blob hashes at commit 3622e58. That would make the check read `company/`, which this ADR and build-readiness decision 12 forbid; it stays with the owner together with P-0-GITIGNORE (build log, "Questions for the owner").

**Licences** (`tools/checks/licences/`).
- npm licences from `pnpm licenses ls --json`, with a fallback that reads each installed `package.json`. Python licences from `tools/checks/licences/python_dists.py`, run with `-I -B` so it writes nothing, over the extractor venv's `site-packages` through `importlib.metadata`.
- SPDX expressions are evaluated: `OR` takes the most permissive branch, `AND` the least permissive part, `WITH` keeps the base licence. Free-text licence fields and trove classifiers are read too.
- Fails on AGPL, GPL, or a licence that is missing or unknown (`UNLICENSED`, `NOASSERTION`, `SEE LICENSE IN ...`), because GPL cannot be ruled out. Reports LGPL, MPL and other weak copyleft licences, and notes a dual licence where one option is GPL.
- For a Python distribution whose metadata says LGPL, the licence files inside the installed wheel are read: GPL text in a folder with no LGPL text beside it fails, with the file path; a `COPYING` (GPL) next to a `COPYING.LESSER` is normal LGPLv3 packaging and is reported.
- 11 seeded bad inputs and 2 good ones.

**Config exclusion** (`tools/checks/config-exclusion/`). It never reads `company/`; company paths are synthetic probes. It inspects:
- `pnpm-workspace.yaml` and `package.json` workspaces;
- every `tsconfig`, following `extends` for `include`, `exclude` and `files`, plus `references`, `compilerOptions.paths`, `typeRoots` and `rootDirs`;
- ESLint, asked through its own API (`isPathIgnored`, `calculateConfigForFile`);
- Vitest (root and projects, including whether a project inherits the root's settings) and Playwright (`testDir`, `testMatch` and `testIgnore` per project), by importing their configs;
- Prettier (config or dependency, then `.prettierignore`);
- dependency-cruiser: a rule of severity error forbidding imports into `company/` from any file, and the scan roots in package scripts against `options.exclude` and `includeOnly`; since round 2 `pnpm lint:deps` names no root (it runs `tools/checks/scan-roots/lint-deps.ts`), so the check also inspects the command that script runs, with the `lint:deps` roots of `tools/checks/scan-roots/roots.json`;
- ruff and pytest settings in `pyproject.toml`, `ruff.toml`, `pytest.ini`, `tox.ini` and `setup.cfg`;
- package scripts and CI job scripts, following `cd`: any argument pointing into `company/`, and ruff or pytest run over the repository root without a root exclusion;
- Tailwind CSS (automatic source detection off, `@source` and `source()` paths, `@source not`);
- the Vite dev server (`server.fs.allow`, `deny` and `strict`; `root`, `publicDir`, `cacheDir`);
- `.gitlab-ci.yml` `changes` patterns and local includes;
- the checks' own scan roots: `DEFAULT_IGNORES` in `tools/checks/lib.ts` must ignore `company/`, and a heuristic flags any `tools/checks` source that uses a glob library or a recursive `readdir` without `DEFAULT_IGNORES` or an explicit `company/` ignore.
- 21 seeded bad trees and one good tree.

**Mockup figures** (`tools/checks/mockup-figures/`, list `tools/checks/mockup-figures.txt`).
- The list is a check list, not app data; nothing imports it. One entry per line: `kind | figure as the spec writes it | spec file:line  # note`, with three kinds: `number` (the value in any number format), `quantity` (the value with its unit or word) and `text` (words, ignoring case, diacritics and spacing). 127 entries: 83 numbers, 38 quantities and 6 texts, among them the mockups' hotel name, the mockups' floor notations and date, and their areas, counts, points, investment and savings amounts, paybacks, percentages, CO₂ tonnes and lifecycle figures.
- **Traceability.** The check fails when an entry's figure is not on its cited spec line, so every entry stays traceable. An edit to a spec that shifts a cited line fails the check until the line numbers are updated; that coupling is deliberate. The CI path filter covers `design/**` and `tools/**`.
- **Matching.** Numbers match in English and Romanian formats, with space or underscore grouping and k, M or mil. scaling; units match in their usual spellings (m² as `mp` or `m2`, `ani`, `tone`). SVG geometry is ignored, and a number glued to an identifier or a hex string is skipped.
- **Scope.** Required: `apps/**`, `packages/*/src/**` and, since round 2 (adversarial finding 14), `services/extractor/src/**`, where phase 2 writes the extractor. Optional: every glob the shared scan-roots list names for this scan (`scanGlobs('mockup-figures')`: `packages/*/{seed,seeds,migrations,templates,test-formulas}/**`, `services/*/src/**`, `fixtures/**`), read from the list at load, and top-level `seed(s)/**`. The case folders `fixtures/evals/G*-*/` are left out (prompt 3 section 14, item 3: case files may use their own case's numbers from guardrails section 7). `tests/` is not read. It fails on any hit, on a missing, empty or malformed list, and on an empty scope.
- **Self-test.** 10 seeded bad inputs: 8 static seeded bad trees against a TEST list and a TEST spec, `bad-extractor-hits` (round 2), and a run-time case that plants every real entry (210 plantings) in a temporary tree and requires each to be found.
- **Limits.** Matching is per line, so a figure split across two lines is missed. Binary fixture files (future PDF and XLSX) are counted, not read; their generators and text fixtures are read. Small or generic mockup values are left out on purpose: counts under 3 digits, setpoints, 800 ppm, tags such as AHU-01, sheet ids A-101 to A-129, people's names, and the specs' own recomputed figures in section 6. Nothing guards the list against an entry being removed: a removal lets more through and is a loosening. Because the list names the hotel, a repository-wide grep for the hotel name must leave out `tools/checks/mockup-figures.txt` (and `design/`).

**Company figures** (`tools/checks/company-figures/`, list `tools/checks/company-figures.txt`; phase 0 review round 2, adversarial finding 8).
- A check list like the mockup-figure list, never app data and never imported, sharing its parser, matcher and scan. 947 entries, each citing its `company/` file and line: 69 figures (12 numbers, 50 quantities, 7 texts: website statistics, reference-project areas, rooms and beds, case-study numbers, project counts, savings, payback and price claims, price bands, and the company's registration numbers) and 878 SAUTER product names (603 article codes, 223 model designations, including "SAUTER <code>" for the bare letter families, and 52 product lines and names).
- A fourth kind, `product`, matches a product or model name as whole words, ignoring case and diacritics, with up to three spaces, hyphens, dots, slashes, colons or underscores between its letter and digit groups, or none where letters meet digits, through a token trie (about 25 ms for the whole planted list).
- **The check never reads `company/`.** The sources were checked once, when the list was built, by matching each entry on its cited line with the check's own matcher; the one-time builder stayed in the session scratchpad. If `company/` is refreshed, cited lines may drift and the ban still holds. Whether a rebuild tool may read `company/` is for the owner.
- A product hit's message states the closed behaviour of the `dataset-sauter-catalogue` gate (no SAUTER product line, product or model name anywhere; G1-3, G2-5). "SAUTER-based", the company description, is not a product name.
- Scope: the mockup-figure scope above. It fails on any hit, on a missing, empty or malformed list, and on an empty scope.
- **Self-test.** 9 seeded bad inputs: 8 static trees against a TEST list (`bad-product-name`, `bad-company-figure`, `bad-extractor-hit`, `bad-seed-and-fixture`, `bad-list-malformed`, `bad-list-empty`, `bad-list-missing`, `bad-empty-scope`) and a run-time case that plants all 947 real entries (1,221 plantings) and requires each to be found.
- When an approved SAUTER catalogue dataset lands (the phase in which `dataset-sauter-catalogue` opens with approval), its file will hold product names; if it sits in this scope, the check flags it. Its home and any exemption are for the approver.

**Scan roots** (`tools/checks/scan-roots/`, list `tools/checks/scan-roots/roots.json`; phase 0 review round 2, adversarial finding 13).
- One list classifies every folder at the top of the repository, under `packages/<pkg>/` and under `services/<service>/` as scanned (with the scans that read it and, at the top, whether the CI path filter names it) or excluded (with the reason). The scans are `lint:deps`, `lint-bans`, `reserved-terms`, `mockup-figures`, `python-bans` and `ruff-pytest`.
- Readers: `pnpm lint:deps` (`lint-deps.ts`), the lint-bans check and its boundary run, the extractor's Python bans, the reserved-term check, the mockup-figure and company-figure checks, the config-exclusion check, and the loosening check's exception-list snapshot (`scan-roots.excluded`, an allow list; `scan-roots.scanned`, a deny list). `tools/checks/scan-roots/wiring.test.ts` pins the checks that take globs to the list.
- The check fails on a folder the list does not classify (`scan-roots/unlisted`), a malformed list (`company/` scanned, an exclusion with no reason, an unknown scan, a subfolder scan its parent lacks), a `lint:deps` script that is not the wrapper, a CI path filter that disagrees with the list's CI marks, and an empty scope.
- 10 seeded bad inputs (among them `scripts/seed.ts`, the finding's own example, and the `lint:deps` script as it was before the fix) and 22 unit tests.

## Consequences

- **Result on 2026-09-25, after round 2:** version sync passes at v1.5 (`CLAUDE.md`, the prompt header, one third-party skill with no line, reported as a note); the fixture manifest passes with 0 files and 0 sources, 0 generators run, 60 extensions and 1,267 files read by content; the mockup-figure check passes (127 entries, 69 files read, no hit); the company-figure check passes (947 entries, 69 files read, no hit); the scan-roots check classifies 36 folders with no problem; the licence check passes over 281 npm packages and 7 Python distributions with no AGPL or GPL, LGPL 0, MPL 4 (`@axe-core/playwright` 4.13.0, `axe-core` 4.13.0, `lightningcss` 1.32.0 and 1.33.0, `lightningcss-darwin-arm64` 1.32.0 and 1.33.0); config exclusion passes over 25 configs.
- A Playwright `toHaveScreenshot` baseline (a PNG under `tests/e2e/`) would fail the document-type rule. Visual baselines, if ever wanted, need a decision on their home first.
- In CI the licence check needs a Python 3.10 or later inside the node image, because the venv artifact links to the python image's interpreter. The `checks` job installs `python3` in its container only when the image lacks it; this has not run anywhere yet, because no GitLab project exists (build-readiness decision 11).
- The IfcOpenShell wheel is not installed yet (phase 2), so the wheel-folder rule has run only on seeded input.
- Config-exclusion approximations: glob matching uses Node's `path.matchesGlob`, which approximates the minimatch, picomatch, fnmatch and tinyglobby rules each tool uses; the scan-root heuristic does not detect a hand-written directory walker that uses neither a glob library nor a recursive `readdir`.
- No section 7 case covers these harness checks; they are covered by unit tests and self-tests.
- **Phase 0 review (2026-09-25).** Finding 6 (no mockup-figure list) and finding 15 (document formats missed) were fixed here, each with seeds the earlier check let through. `.gitignore` does not ignore the new document formats yet: prompt 3 section 12 allows only lines for generated output, so the matching lines are proposed in the build log. They are harness near misses with no section 7 case; the change-log row is owed when phase 1 next edits `docs/guardrails.md`.
- **Phase 0 review, round 2 (2026-09-25).** Adversarial findings 8 (company figures and SAUTER names unread), 9 (fixture hashes never reproduced, homes open to every type, embedded documents), 13 (fixed scan roots) and 14 (the extractor outside the figure scope), and finding 15 of the second verification (media and SVG exports), were fixed here, each with seeds the earlier checks let through. Every change flags more. The document-home types, the scan-roots exclusions and scans, and the company-figure list are in the loosening check's exception-list snapshot (ADR 0010). A new folder in the repository now needs a line in `roots.json`, and an excluded one needs the approver (a loosening); a new scanned one is recorded by the baseline writer.

## How to reverse

- Version sync: exempt a file by removing it from the list the check reads; narrowing the list is a loosening of section 10's "CI fails when it differs".
- Fixture manifest: the schema is versioned; a version 2 needs the check and every manifest entry changed together. Adding a home for document-type files lets more through and is listed for review.
- Licences: an allowlist of reviewed unknown licences could be added to `licences.ts`; none exists or is needed today. Allowing GPL anywhere needs the owner (prompt 3 section 13, item 7).
- Config exclusion: drop an inspector from `inspect.ts`. Each inspector removed lets a config reach `company/` unnoticed, so it is listed for review first.
- Mockup figures: drop the check folder and `mockup-figures` from `EXPECTED_CHECKS`, or remove an entry from the list. Either lets more through and is listed for review first. Section 14 item 3 would then be a manual grep again.
- Company figures: the same, for `company-figures` and its list; removing an entry fails the loosening check until approved.
- Scan roots: as in `tools/checks/scan-roots/README.md`, "How to reverse"; it lets new folders go unread, so it is listed for review first.
