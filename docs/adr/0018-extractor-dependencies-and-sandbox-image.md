# 0018. Extractor dependencies, the sandbox image, and the IfcOpenShell licence stop

- **Status:** Accepted: default, reversible (the locks, the images and the licence-check change). **Accepted: owner decision 2026-09-26** for how IFC models are read: option (c), "web-ifc instead (Recommended)". IfcOpenShell 0.8.5 and IfcTester 0.8.5 are not used; see "The stop" and "The owner's decision" below, and ADR 0031 for the IFC reader.
- **Date:** 2026-09-26; amended 2026-09-30 (decision 5: committing the draft IDS)

## Context

- **Prompt 3 section 5.2, row "Extractor"** (build-readiness 3 "Now" item 5; ifc-input 2.2): a Python service with IfcOpenShell 0.8.5 and IfcTester 0.8.5 pinned, pypdfium2 and openpyxl; no PyMuPDF (AGPL), no OCR. PRD section 13, "Build recommendations", row "The extractor": Proposed, D id **D-01**. The owner decided no D row, so the 5.2 default applies with this ADR.
- **Prompt 3 section 8, "Licences"** (ifc-input 2.3): a licence check that fails on AGPL or GPL and reports LGPL and MPL; "Package metadata lists IfcOpenShell as LGPL only, so also inspect the licence files inside the wheel. If a bundled geometry component is GPL, stop (section 13, item 7) and choose a kernel that avoids it." ifc-input 2.3 names the risk: CGAL is "LGPL or GPL, by component". PRD row "A third-party notices page and a licence check": D-94.
- **Prompt 3 sections 8 and 11**: every job that opens an owner model or document runs in a container with no network, a read-only input mount, and memory and time limits. Section 12, "Dependencies and downloads": packages from npm and PyPI only, pinned; the Docker Hub base images pinned by digest and the IDS 1.0 XSD are approved downloads (build log, "The owner's answers", item 2; prompt 3 names standards.buildingsmart.org as its source, and after that site's bot challenge the owner decided on 2026-09-26: "Fetch from buildingSMART's GitHub"); no binary from GitHub.
- **Machine:** macOS arm64, Python 3.12.14, Docker 29.5.2 through Colima (linux/arm64, classic builder; no buildx plugin).

## The stop: IfcOpenShell 0.8.5 and IfcTester 0.8.5 bundle GPL geometry code

Inspected on 2026-09-25/26 from PyPI (`pip download`, into the scratchpad; nothing installed into the project):

1. **No licence file in either wheel.** `ifcopenshell-0.8.5-py312-none-macosx_11_0_arm64.whl` (42.4 MB), the `manylinux_2_31_x86_64` wheel (43.7 MB) and `ifctester-0.8.5-py3-none-any.whl` (25.4 MB) carry `METADATA`, `WHEEL`, `RECORD` and `top_level.txt` in `.dist-info`, and no LICENSE, COPYING or NOTICE file anywhere. The metadata declares only the classifier "GNU Lesser General Public License v3 or later (LGPLv3+)".
2. **The compiled library bundles CGAL's GPL packages.** `ifcopenshell/_ifcopenshell_wrapper.cpython-312-*.so` (158 MB on macOS; statically linked: it depends only on the system C and C++ libraries) contains symbols of these CGAL packages: 3D Boolean Operations on Nef Polyhedra (`Nef_polyhedron_3`, 249 matches in the Linux binary), Polygon Mesh Processing, 2D Straight Skeleton and Polygon Offsetting, 2D Arrangements, 2D Regularized Boolean Set-Operations, AABB Tree, Intersecting Sequences of dD Iso-oriented Boxes, 2D Triangulations and 3D Polyhedral Surface. CGAL's Package Overview (`https://doc.cgal.org/latest/Manual/packages.html`, read 2026-09-25) lists each of them with "License: GPL"; its kernel and support packages (also present) are LGPL. CGAL's licence page: "most geometric algorithms and data structures are under the GPL". OpenCASCADE is linked in too (the `OpenCascadeKernel`).
3. **IfcTester ships the same code again**: `ifctester/webapp/www/worker/bin/ifcopenshell-0.8.5+a51b2c5-cp313-cp313-pyodide_2025_0_wasm32.whl`, a WebAssembly build of IfcOpenShell whose library carries the same CGAL GPL packages, inside a browser web app bundled in the wheel (with Pyodide).
4. **The phase 0 licence check passed both** ("LGPL 2", no failure), because it read licence files and the wheels have none. That is a near miss; the check now reads the binaries (below).

Under prompt 3 section 8 and section 13 item 7 this stops the IfcOpenShell and IfcTester part of phase 2. Neither is in any lock, the project virtual environment or the image. What stays blocked: the IFC fixture generator (it authors with `ifcopenshell.api`), the four IFC fixtures and their ground truth, the IFC extractor pipeline, `ifcopenshell.validate`, the IfcTester run with the draft IDS v0.1 and its expected results, and the `tests/proposed/` IFC suite. What does not depend on it goes ahead: PDF and XLSX reading, uploads, the queue, the AI boundary, the verifier and the eval runner.

**Options for the owner** (none taken; each is the owner's call, with counsel's view before any release, ifc-input 2.3):
- **(a) Use the PyPI wheels for local development only**, on synthetic fixtures, accepting that the binary includes GPL-3.0-or-later CGAL code. Running it on one's own machine or server does not by itself distribute it (ifc-input 2.3, "Hosted use"); distributing it (on-premise, desktop) would bring GPL obligations. The licence check would then need a reviewed exception naming the two distributions and the reason: an exception list entry, which waits for the approver (guardrails section 10; ADR 0010).
- **(b) Build IfcOpenShell 0.8.5 from source without CGAL** (OpenCASCADE-only geometry), in the image build. Needs the IfcOpenShell, OpenCASCADE and Boost sources (not on PyPI, so a new download to approve), a long native build, and IfcTester installed without its bundled web app. The data pass (header, units, spatial tree, property sets) does not need CGAL; geometry-derived values sit behind `ifc-geometry` anyway.
- **(c) A different parser for the data pass**, such as web-ifc (MPL-2.0) in the Node sandbox, with IDS checking from another tool or none. A change to prompt 3 5.2's extractor default (D-01) and to ifc-input 2.2.
- **(d) A commercial CGAL licence** from its publisher, if IfcOpenShell's own build is kept.

**The owner's decision (2026-09-26),** asked in the session and recorded in the build log ("Owner answers during the run") with the owner's words: **"web-ifc instead (Recommended)"**, option (c). What it settles:
- **IFC data is read with web-ifc** (MPL-2.0; `web-ifc` 0.0.78 from the npm registry, pinned in `pnpm-lock.yaml`), in its own no-network sandbox, as the viewer's conversion will in phase 4: the IFC reader, `packages/ifc-reader` (ADR 0031). The API's worker sends it every IFC job, and the Python extractor PDF and XLSX jobs.
- **The in-house STEP reader stays only for word-for-word evidence excerpts**: a fact's verbatim STEP line and its literal tokens (`services/extractor/src/sovitech_extractor/ifc/step.py`, and its TypeScript copy in the reader; the two read one shared corpus). The schema tables ADR 0024 wrote for the Python data pass are superseded and removed.
- **IfcOpenShell, its schema validator (`ifcopenshell.validate`) and IfcTester are not used**, so neither enters a lock, the venv or an image, and the licence stop above needs no exception. The IDS model check waits (a recommendation, D-36): no IDS result arises, live or in tests of the reader; the scripted-output case G12-6 keeps what it proves. The reader's own exchange-structure check (ISO 10303-21 and the two readers' agreement on each instance) is recorded as the contract's schema check, named as such (ADR 0031); it is not a schema validation.
- **The IDS 1.0 XSD** comes from the official buildingSMART/IDS GitHub repository ("Fetch from buildingSMART's GitHub"; decision 5 below and `services/extractor/schemas/README.md`).
- **Counsel still reviews MPL-2.0** before any release (D-94; ifc-input 2.3: sending web-ifc's WASM to browsers, in phase 4, is distribution).
- **Also changed:** prompt 3 5.2's extractor default ("Python service with IfcOpenShell 0.8.5 and IfcTester 0.8.5") and ifc-input 2.2's stack no longer describe the build; both are documents this build does not edit: listed for the build log's "Product doc issues".

## Decision

1. **Python locks** in `services/extractor/`, each compiled with pip-tools 7.6.1 on Python 3.12 (`--generate-hashes --strip-extras --no-emit-index-url --allow-unsafe`), every version hashed with the SHA-256 of every file PyPI publishes for it:
   - `requirements.in` -> `requirements.lock`, the extractor runtime: **pypdfium2 5.13.0** (Apache-2.0 or BSD-3-Clause; bundles PDFium, BSD-3-Clause, with its third-party licences in the wheel), **openpyxl 3.1.5** (MIT) with **et-xmlfile 2.0.0** (MIT), **lxml 6.1.3** (BSD-3-Clause; for validating the draft IDS against the XSD).
   - `requirements-fixtures.in` -> `requirements-fixtures.lock`, the fixture generators, constrained by the runtime lock: **reportlab 5.0.1** (BSD; invariant mode for byte-identical PDFs) with **pillow 12.3.0** (MIT-CMU) and **charset-normalizer 3.5.1** (MIT), and **PyYAML 6.0.3** (MIT) for building specs and ground truth.
   - `requirements-dev.in` -> `requirements-dev.lock`, the local environment: both sets plus the phase 0 tools (ruff 0.16.9, pytest 9.1.1, and pytest's iniconfig 2.3.0, packaging 26.3, pluggy 1.6.0, Pygments 2.21.0). 14 distributions, plus pip.
   - **Platforms checked**: `pip download --require-hashes --only-binary=:all:` resolves every lock to hashed wheels for macOS arm64 (macOS 13+), Linux x86_64 and Linux aarch64 (glibc 2.36, manylinux tags down to 2014). No source distribution is needed anywhere.
   - **Regenerating**, from `services/extractor/`, in order (each later lock is constrained by the earlier ones): `requirements.lock`, then `requirements-fixtures.lock`, then `requirements-dev.lock`, each `pip-compile <flags> --output-file=<lock> <in>` from a throwaway pip-tools venv outside the repository (ADR 0001). Then check the three platforms as above.
2. **Installs are hashed and wheel-only.** `pnpm setup:py` and the CI `.python` job run `python3.12 -m venv --clear services/extractor/.venv` and `pip install --require-hashes --only-binary=:all: -r services/extractor/requirements-dev.lock`: pip refuses a changed file or an unlisted dependency, runs no package build script, and `--clear` removes anything a lock no longer lists, so the licence check reads exactly the lock.
3. **The sandbox image**, `services/extractor/Dockerfile`, with the build context limited to this folder by `.dockerignore` (the locks and `src/` only):
   - base **`python:3.12.14-slim-bookworm@sha256:392307d22300de8b5986851a12d9176dfc0fc073e65bf6523ebd7dcbeb23564e`** (the multi-platform index; linux/amd64 `sha256:1aaa65a85fda306ffb8b910824d4e93bdce61e212c7e87168123ea3073b41a1a`, linux/arm64 `sha256:eb5be8e5b4d0a159c237946bbdd06356dda5d19c30fc4f7843e8046d3a590333`), pulled 2026-09-25;
   - target **`extractor`**: a venv in `/opt/venv` installed from `requirements.lock` with `--require-hashes --only-binary=:all:`, the package source in `/opt/extractor/src` found through a `.pth` file (so `python -I` works), an unprivileged account (uid and gid 10001, no home, no shell), `ENTRYPOINT ["python", "-I", "-m", "sovitech_extractor"]`. 268 MB on linux/arm64;
   - target **`fixtures`**: the same plus `requirements-fixtures.lock`, `ENTRYPOINT ["python", "-I"]`, for regenerating fixtures offline. 318 MB;
   - **run-time limits are the runner's**, as the Dockerfile header lists: `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --pids-limit`, `--memory` equal to `--memory-swap`, `--cpus`, a small `noexec` tmpfs at `/tmp`, the input file mounted read-only, one writable output mount, and a wall-clock kill. The image holds no secret.
   - **Built once on 2026-09-26** (both targets, linux/arm64): with those flags, `socket.create_connection` fails (`gaierror`), a write to `/opt` fails (read-only root), the process runs as uid 10001, and pypdfium2 (PDFium 153.0.7999.0), openpyxl 3.1.5, lxml 6.1.3, reportlab 5.0.1 and PyYAML 6.0.3 import. `sovitech_extractor` had no `__main__` then; the extractor's entry point came later in phase 2 (ADR 0024), and the image was rebuilt from it.
4. **The Node sandboxes** build on **`node:22.17.1-bookworm-slim@sha256:2fa754a9ba4d7adbd2a51d182eaabbe355c82b673624035a38c0d42b08724854`** (index; linux/amd64 `sha256:ffb27ca0f26a231a08930c872631cea70cbb318463d1e712922b5c7cfdc3fcca`, linux/arm64 `sha256:f31365dd54da647fa44463f9b70391c748ffcf5e0ec0960115ab4b032d1f89ec`), pulled 2026-09-25, matching the machine's Node 22.17.1: since the owner's decision of 2026-09-26, the IFC reader's image (`services/ifc-reader/Dockerfile`, built from the repository root with the root `.dockerignore`; ADR 0031), and in phase 4 the viewer's conversion (That Open's IfcImporter; prompt 3 section 8), which has no Dockerfile yet.
5. **The IDS 1.0 XSD is fetched from the official buildingSMART/IDS GitHub repository** (owner decision 2026-09-26: "Fetch from buildingSMART's GitHub", after `https://standards.buildingsmart.org/IDS/1.0/ids.xsd` answered a non-browser request with a bot challenge, HTTP 403 `cf-mitigated: challenge`, which the build did not try to get past): tag v1.0.0, commit `1effec6f419798ce09617416d258a35bdc58320a`, `Development/ids.xsd`, SHA-256 `8975dc18bd18f08a345a430a22bf317a54d94671b7db01400042fa43b6c0d1f3` (git blob `edab179d836d0c3e9b21d93c5e2b29f86ec56885`, 13,158 bytes), stored unchanged as `services/extractor/schemas/ids-1.0.xsd` (CC BY-ND 4.0, (c) buildingSMART International Ltd.; attribution in `services/extractor/schemas/README.md`). It is a data file; nothing runs it, and it is not in any image. lxml compiles it offline only with `services/extractor/schemas/xs-namespace-stand-in.xsd`, a SOVITECH-written stand-in for the W3C XMLSchema.xsd import that declares `xs:restriction` and `xs:occurs` only, each a stricter subset of the W3C definition (the W3C file was not downloaded; replacing the stand-in with it is a new download for the owner). The draft IDS v0.1 validates against it with no change (`services/extractor/tests/test_ids_schema.py`, F-IFC-09, 16 tests, with ten broken copies that each fail for their own reason). The IDS-Audit-tool is not run (a binary from GitHub, prompt 3 section 12) and IfcTester is not used (the owner's decision above), so nothing checks the IDS beyond the XSD, and the IDS model check waits (D-36). **Committing the draft IDS** (the orchestrator's ruling of the phase 2 review round, 2026-09-30, under prompt 3 section 8's "validated as section 12 describes before you commit it"): the draft IDS v0.1 is committed, labelled draft reference data, on its validation against the IDS 1.0 XSD with lxml; section 12's IfcTester half is not applicable by the owner's decision of 2026-09-26 (IfcTester is not used), and the IDS-Audit-tool was not run. Its expected-result files keep their text (their `about` line still says IfcTester is "withheld"), so their hashes do not change.
6. **The licence check reads native binaries** (ADR 0009, "Licences"): every shared library, extension module and WebAssembly file a wheel installs, and those in an archive it ships, is searched for the symbol names of CGAL's GPL packages; any hit fails whatever the metadata says, and an LGPL wheel with native binaries and no licence file fails as "not stated". Over the new environment it passes with no hit (15 distributions; pillow, lxml, pypdfium2, PyYAML and charset-normalizer carry native code and licence files). Against the two withheld wheels, installed into a scratchpad venv only, it fails four times: GPL components in each, and no licence file in each.

## Consequences

- Phase 2's IFC work waited for the owner's decision, which came on 2026-09-26 (web-ifc; ADR 0031). The `ifc-values` gate and its companions stay closed in any case; the stop was about the tool, not the gate.
- The extractor sandbox holds only what reads documents; the fixture generators' dependencies (reportlab and Pillow among them) are in a separate target, so the sandbox that opens owner files carries no PDF writer or image library it does not use.
- The dev environment holds the union, so `pnpm test:py`, the fixture-manifest check's generator runs and the licence check all read one venv.
- `pnpm setup:py` now recreates the venv each time (`--clear`); pip's cache keeps it quick.
- npm native binaries and WebAssembly (esbuild, lightningcss, and web-ifc's WASM since phase 2) are not scanned by the binary search; their licences come from package metadata only (web-ifc: MPL-2.0, reported as MPL). ADR 0031 records a one-off search of `web-ifc-node.wasm` for the CGAL GPL package symbols this search uses: no hit.

## How to reverse

- **Another extractor dependency or version:** change the `.in` file, regenerate the locks in order, re-run the three-platform `pip download` check and `pnpm setup:py`, rebuild the image, and record it here.
- **One image instead of two targets:** move the fixtures lock into the runtime lock; the sandbox then carries reportlab and Pillow.
- **Undo the binary search:** drop `nativeFiles` and `bundledGpl` from `python_dists.py` and `binaryFindings` from `licences.ts`, and the three seeded cases. That lets a wheel like IfcOpenShell 0.8.5 pass again, so it is a loosening of the check and waits for the approver.
- **The owner's decision on IfcOpenShell** (option (c), web-ifc) is the owner's to change. Back to option (a): add `ifcopenshell==0.8.5` and `ifctester==0.8.5` to `requirements.in` with a reviewed licence-check exception (the approver's), and route IFC jobs to the extractor again (ADR 0031, "How to reverse"); option (b): a source build stage in the Dockerfile and a wheel built from it; option (d): a commercial CGAL licence. Any of them brings `ifcopenshell.validate` and IfcTester back for the schema and IDS checks.
